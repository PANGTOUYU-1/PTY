# 数据结构参考

`data/site-data.js` 里每个字段的完整说明。写内容时当字典查。

---

## 顶层结构

| 键 | 类型 | 必填 | 作用 |
|---|---|---|---|
| `meta` | object | ✅ | 站点标题、作者、版本、外链、页脚 |
| `categories` | array | ✅ | 物品分类表 |
| `characters` | array | ✅ | 角色（**必须且只能 2 个**） |
| `items` | array | ✅ | 物品 |
| `mechanics` | array | ✅ | 机制 |
| `terrains` | array | ✅ | 地形 |
| `changelog` | array | ✅ | 更新日志 |
| `seasons` | array | ⬜ | 季节（走「扩展字段」自动发现） |
| `skins` | array | ⬜ | 物品外观，由 `item_id` 归入对应物品详情，不单列分区 |
| `posters` | array | ⬜ | 首页海报轮播 |
| `sections` | array | ✅ | 分区定义，决定导航与页面块 |
| `relations` | object | ⬜ | 手动覆盖 `id → 展示名` 映射 |

> **扩展字段**：除了上表的固定键，任何**新增的数组字段**都会被 `assets/js/data.js` 自动发现，加入搜索索引和 `[[双链]]` 名称表。`seasons` 就是这么工作的。

## `categories`

```js
{ "id": "weapon", "name": "武器" }
```

| 字段 | 说明 |
|---|---|
| `id` | 被 `items[].category` 引用 |
| `name` | 筛选面板与卡片上显示的中文名 |

当前已有：`weapon` 武器、`armor` 护具、`tool` 工具、`structure` 建筑、`food` 食物、`crop` 作物、`material` 材料、`misc` 其他。

新增分类只需加数组元素，筛选按钮自动出现。

## `characters`（角色）

⚠️ **硬约束**：`assets/js/data.js` 里把两个角色 id 写死为 `pangtouyu`（左）和 `gaojiaoniao`（右）。**改 id 会导致首页塌掉**。超过 2 个角色不会被渲染。

```js
{
  "id": "pangtouyu",
  "side": "zuo",                       // zuo=左 / you=右
  "name": "胖头鱼",
  "epithet": "角色外号",                // 可被全局搜索命中
  "portrait": "assets/img/characters/pangtouyu_head.png",
  "featured_items": ["bighead_spear", "bighead_fanhua", "bighead_armor", "bighead_back"],
  "stats": { "hp": 150, "san": 200, "hunger": 150 },
  "setting": ["设定条目1", "设定条目2"],
  "exclusive_intro": ["专属介绍第一段", "……"]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | **必须是 `pangtouyu` / `gaojiaoniao`** |
| `side` | string | `zuo` 显示在左，`you` 显示在右 |
| `featured_items` | string[] | 首页悬停立绘时展示的专属物品 ID，当前每人四件；必须归属该角色并有 `display_image`。桌面胖头鱼的物品显示在右上，高脚鸟的显示在左上，连线指向当前立绘；另一角色隐藏且不可聚焦，关闭后恢复。窄屏在立绘下展开，点击图片可查看物品详情。 |
| `name` | string | 角色名，参与搜索与双链 |
| `epithet` | string | 外号/称号，参与搜索 |
| `portrait` | string | 立绘路径 |
| `stats.hp` / `san` / `hunger` | number | **必须是数字**，显示为 `HP 150 / SAN 200 / HUNGER 150` |
| `setting` | string[] | 「设定」按钮点开后的逐条内容 |
| `exclusive_intro` | string[] | 「专属」按钮点开后的逐段内容 |

> 点击角色卡片不是在弹窗里打开，而是在首页弹出角色浮层（`assets/js/char-popup.js`）。

## `items`（物品）

```js
{
  "id": "item_inkstone",
  "name": "占位物品1",
  "category": "tool",
  "owner": "pangtouyu",
  "image": "assets/img/items/testitem.png",
  "display_image": "assets/img/displays/testitem.png",
  "summary": "简介",
  "recipe": "[res_stone] ×1  [res_charcoal] ×1",
  "tech": "所需科技",
  "detail_blocks": [ ... ],
  "related": ["pangtouyu", "item_brush"],
  "tags": ["标签1", "标签2"]
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 唯一标识 |
| `name` | string | ✅ | 显示名，参与搜索与双链 |
| `aliases` | string[] | ⬜ | 别称，同样参与搜索与双链；不得与其他条目的名称或别称冲突 |
| `category` | string | ✅ | 必须是 `categories` 里的 id，否则显示为「其他」 |
| `owner` | string | ✅ | `pangtouyu` / `gaojiaoniao` / `common` |
| `image` | string | ✅ | 小图标路径，名称前和配方以 24px 展示 |
| `display_image` | string | ⬜ | 落地展示图，供卡片与详情大图使用；不替代配方图标 |
| `summary` | string | ⬜ | 卡片摘要，使用普通文字；关联词链接放在详情正文 |
| `availability` | string | ⬜ | 获取状态，支持「未实装」「特殊获取」；在物品卡片与详情顶部显示，并参与搜索 |
| `recipe` | string | ⬜ | 配方，`[id]` 渲染成素材图标；空字符串表示无配方 |
| `tech` | string | ⬜ | 所需科技，纯展示文本 |
| `detail_blocks` | array | ⬜ | 详情图文块，见下 |
| `related` | string[] | ⬜ | 关联条目 **id** 列表 |
| `tags` | string[] | ⬜ | 标签，参与搜索 |

## `detail_blocks`（详情图文块）

`display_image` 同样适用于机制、地形、节气与外观。通用卡片和详情优先使用此字段，
其次使用独立的 `illustration`；只有 `image` 时仅在名称旁显示小图标，不将其放大为主图。
展示图由 `tools/export_mod_displays.py` 调用 DST Mod Tool 原生导出，来源清单位于
`data/display-assets.json`，不要对这些 PNG 再上下翻转或用小图标覆盖。

支持段落、图片、列表、表格和属性数值：

```js
// 段落
{ "type": "text", "content": "支持 [[双链]] 的正文。" }

// 图片
{ "type": "image", "src": "assets/img/items/xxx.png", "caption": "图片说明" }

// 省略 type 时按段落处理（content 里写文字）
{ "content": "也可以不写 type" }

// 列表，每条独立呈现
{ "type": "list", "title": "使用步骤", "items": ["先获取材料。", "再使用 [[琦玉器]]。"] }

// 条件与效果表，rows 每行的单元格数量必须与 columns 一致
{
  "type": "table", "title": "领悟条件",
  "columns": ["道", "条件", "属性变化"],
  "rows": [["神道", "初始领悟", "无额外变化"], ["恶鬼道", "饥饿死亡", "饥饿上限 +50"]]
}

// 并排属性，value 使用字符串，unit 可省略
{
  "type": "stats", "title": "五道圆满后的三维上限",
  "stats": [{ "label": "生命", "value": "200" }, { "label": "理智", "value": "150" }, { "label": "饥饿", "value": "250" }]
}

// 提示块（tone 也可用于其他类型）
{ "type": "text", "tone": "note", "title": "注意", "content": "先确认触发条件。" }
```

| 字段 | 说明 |
|---|---|
| `type` | `"text"` / `"image"` / `"list"` / `"table"` / `"stats"`；省略时按段落处理 |
| `content` | `text` 类型的正文，支持 `[[双链]]`；用 `\n` 分隔段落 |
| `title` | 可选小标题，显示在该段正文前；物品使用「怎么使用」「效果与限制」等玩家能理解的标题 |
| `src` | `image` 类型的图片路径 |
| `caption` | `image` 类型的说明文字 |
| `items` | `list` 类型的文字数组，支持 `[[双链]]` |
| `columns` / `rows` | `table` 的表头与二维文字数组；首列作为行标题，单元格支持 `[[双链]]` |
| `stats` | `stats` 类型的属性数组，元素包含 `label`、`value`，可选 `unit` |
| `tone` | 可选 `"note"`，为提示块加浅底与强调边线 |

连续的图片块横向排列，说明位于各自图片下方；宽度不足时自动换行。文字块仍独占一行，保持图文原有顺序。
段落、列表和表格内的数字自动强调，关联词仍可点击。详情块中的文字均加入搜索索引。
条件、概率和效果优先用表格对照，关键上限用属性块，操作步骤用列表；不要将所有规则塞进一个段落。

物品的 `summary` 用一句话说明实际用途，避免只放诗句或检查台词。
`detail_blocks` 先写使用操作、触发条件和消耗，再写升级、获取与维护；检查台词放末尾。
`owner` 表示实际使用限制，制作角色限制单独写入 `tech`／`recipe`，不要把角色可制作的通用食物标成专属食物。
物品筛选栏提供分类与关键词筛选，分类每次只能选中一项，点击当前分类仍保持选中，“全部”恢复完整列表。手机端使用同一筛选抽屉；“清空”同时重置分类和关键词。旧多分类链接只采用第一项。
角色归属在展示图右上角以红色印章标注：胖头鱼为“鱼”，高脚鸟为“鸟”；印章保留完整归属说明供悬停和屏幕阅读器读取，不再在卡片底部重复角色标签。通用物品仍标注“通用”。旧链接的 `owner` 参数不参与筛选，避免隐藏条件漏掉物品。

原版材料图标索引在 `data/vanilla-icons.js`，与 Wiki 条目分开。配方中的「材料名×数量」
会显示为 24px 原版 icon 与文字，材料和数量作为整体换行；「×至少1」同样支持。
例如 `冰×6 + 月亮碎片×6`、`蜂蜜×至少2`。水果度、蔬菜度、理智消耗等不当作物品加图标。

详情通过 `App.Recipe.toBlockHtml()` 将取得方式与材料分层显示；多套配方按「方案」分行，
材料与用量作为整体横向排列并自动换行。`；或` 分隔替代配方，材料后的
`；金企鹅兑换：` 等新方式也单独成行。每套配方中的 `+` 或 `；` 分隔材料与条件，
不会拆开 `×至少1` 这样的数量限定。`toHtml()` 仍用于单段材料与链接渲染。
原版材料仅展示，不生成不存在的详情链接；`[模组条目id]` 继续可点击跳转。

索引的正式名称来自游戏本地 `scripts/languages/chinese_s.po`，旧文案里的金色羽毛、草、
活木、伏特羊奶与鱼肉通过别称对应原版 prefab，不更改现有配方措辞或数量。
四个 `assets/img/inventoryimages1` 至 `inventoryimages4` 目录保留原始 PNG，不翻转或放大。
需要重建当前配方用到的索引时，运行 `python tools/build_vanilla_icons.py --strings <chinese_s.po路径>`。

## `skins`（物品外观）

外观数据保留在 `skins` 数组中供搜索和关联词使用，`sections` 不再配置外观栏目。
每款外观必须有 `item_id` 指向其所属物品，并与物品保持 `related` 双向关联。

```js
{
  "id": "bighead_spear_skin1",
  "item_id": "bighead_spear",
  "name": "涟漪 · 避尘",
  "image": "assets/img/skins/bighead_spear_skin1.png",
  "display_image": "assets/img/displays/bighead_spear_skin1.png",
  "summary": "避尘的装备外观。",
  "related": ["bighead_spear"]
}
```

物品卡片显示外观数量，详情以横向图片卡展示各款外观，窄屏自动换行。
点击可查看外观详情，再通过「返回物品」按钮回到所属物品；外观不重复显示为关联按钮。
搜索外观名字同时能找到所属物品。外观详情使用 `#items/外观id`；旧 `#skins/外观id`
仍能打开详情，旧 `#skins` 定位到物品分区。

## `relations`（手动名称映射）

默认为空 `{}`。`id → 展示名` 的映射由程序自动从 `name` / `title` 生成；如果你想让某条目在双链里显示成**另一个名字**，在这里手动指定，手动值优先。

自定义展示名影响「关联」按钮的名称，正式名称仍可通过 `[[名称]]` 跳转。
一个条目有多个叫法时使用通用字段 `aliases`，例如莲令的 `"aliases": ["貔貅"]`、
何三宝的 `"aliases": ["三宝"]`。正文中的 `[[貔貅]]` 会显示原词并打开莲令条目。
名称、标题、自定义展示名与别称都必须只对应一个有效条目。

```js
"relations": {
  "item_inkstone": "墨石（别称：玄石）"
}
```

## 三个魔法语法速查

| 语法 | 位置 | 说明 |
|---|---|---|
| `[[名称]]` | `changes` / `setting` / `exclusive_intro` / 详情块的 `content`、`items`、`rows` | 打开对应详情；名称需与条目的正式名称、展示名或别称**完全一致** |
| `[id]` | `recipe` | 渲染为可点击的「小图标 + 名字」，打开材料详情 |
| `?editor=1` | 浏览器地址栏 | 打开校阅面板 |

## 路由（URL hash）

站内状态全在 hash 里，可以直接分享链接：

| 链接 | 效果 |
|---|---|
| `#items` | 跳到物品分区 |
| `#items/item_inkstone` | 打开某物品详情弹窗 |
| `#items?cat=weapon` | 只看武器（分类单选） |
| `#items?q=墨石` | 带搜索词 |
| `#序` | 序章 |

## 已知限制汇总

| 限制 | 位置 | 说明 |
|---|---|---|
| 角色 id 硬编码 | `assets/js/data.js` `normalizeCharacters` | 只认 `pangtouyu` / `gaojiaoniao`，且只渲染 2 个 |
| 归属标签硬编码 | `assets/js/data.js` `App.config.ownerLabels` | 新角色的卡片需补充归属标签 |
| 容器 id 硬编码 | `assets/js/render.js` `renderItems` / `renderChangelog` | `items-root` / `changelog-root` |

| 角色立绘文件名硬编码在数据里 | `site-data.js` `characters[].portrait` | 走数据，改数据即可 |
