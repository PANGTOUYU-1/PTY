# 内容写作指南

写给**往站里填内容**的人。只要会改 `data/site-data.js`，不需要懂前端。

---

## 0. 一句话流程

```
改 data/site-data.js  →  python tools/serve.py  →  浏览器看效果  →  ?editor=1 检查  →  提交
```

---

## 1. 先理解三件事

### 1.1 所有内容都在一个文件里

`data/site-data.js` 的结构是：

```js
window.SITE_DATA = {
  meta:      { ... },   // 站点标题、作者、版本、外链
  categories:[ ... ],   // 物品分类
  characters:[ ... ],   // 两个角色
  items:     [ ... ],   // 物品
  mechanics: [ ... ],   // 机制
  terrains:  [ ... ],   // 地形
  seasons:   [ ... ],   // 季节
  changelog: [ ... ],   // 更新日志
  posters:   [ ... ],   // 首页海报
  sections:  [ ... ]    // 分区顺序与标题
};
```

**没有数据库、没有后台、没有构建**。改完保存，刷新浏览器就是新内容。

### 1.2 每条内容都要有一个唯一 `id`

`id` 是程序用的内部标识，**不能重复、不能有空格**，建议用英文+下划线：

| 好的 id | 不好的 id |
|---|---|
| `item_ink_stone` | `物品1` |
| `mech_yinyang` | `阴阳 机制` |
| `terrain_bamboo` | `bamboo-grove`（短横线能用但不推荐） |

`id` 一旦定下来并且被别的条目 `related` 引用了，**就不要再改**，否则会变成死链。

### 1.3 三个「魔法语法」

| 写法 | 用在哪 | 效果 |
|---|---|---|
| `[[物品名]]` | `summary`、`detail_blocks[].content`、`setting`、`exclusive_intro`、`changes` | 渲染成可点击的站内跳转按钮。名称必须是**已有条目的 name 或 title** |
| `[item_id]` | 只在 `recipe` 里 | 渲染成「图标 + 名字」的配方素材块 |
| `{...}` | ❌ 千万别自己写 | 那是模板占位符，只在 `index.html` 里用 |

举例：

```js
"summary": "用[[墨石]]研磨后制成，是[[占位物品2]]的前置。",
"recipe": "[res_stone] ×2  [res_charcoal] ×1  [item_inkstone] ×1"
```

## 2. 写一个物品（最常见的活）

在 `items: [ ... ]` 里加一条：

```js
{
  "id": "item_bamboo_brush",          // 唯一 id
  "name": "竹节笔",                    // 显示名（必须写，不然卡片是空的）
  "category": "tool",                 // 必须在 categories 里
  "owner": "gaojiaoniao",             // 角色 id，或 "common" 表示通用
  "image": "assets/img/items/bamboo_brush.png",
  "summary": "一句话简介，会显示在卡片上。",
  "recipe": "[res_stone] ×1  [res_charcoal] ×1",
  "tech": "无需科技",                  // 纯展示文本，可以直接写"无"
  "detail_blocks": [
    { "type": "text", "content": "第一段说明。可以链接到 [[占位机制1]]。" },
    { "type": "text", "content": "第二段说明：数值、耐久、上限等。" },
    { "type": "image", "src": "assets/img/items/bamboo_brush_detail.png", "caption": "游戏内截图" }
  ],
  "related": ["res_stone", "mech_yinyang"],   // 只写存在的 id
  "tags": ["工具", "高脚鸟"]
}
```

### 检查清单

- [ ] `id` 没和别人撞
- [ ] `category` 在 `categories` 列表里（写错会显示成「其他」）
- [ ] `owner` 是 `pangtouyu` / `gaojiaoniao` / `common` 三者之一
- [ ] `image` 指向的文件**真的存在**（大小写要对，Windows 不敏感但 Linux 服务器敏感！）
- [ ] `related` 里每个 id 都存在
- [ ] `recipe` 里的 `[xxx]` 都是真实 id
- [ ] `detail_blocks` 的 `type` 只能是 `"text"` 或 `"image"`

## 3. 图片规范

### 3.1 放哪

| 用途 | 目录 | 建议命名 |
|---|---|---|
| 物品图标 | `assets/img/items/` | `物品id.png`，如 `item_brush.png` |
| 角色立绘 | `assets/img/characters/` | `角色id_head.png` |
| 机制配图 | `assets/img/mechanics/` | `机制id.png` |
| 地形图标 | `assets/img/terrains/` | `地形id.png` |
| 首页海报 | `assets/img/poster/` | `1.png`、`2.png`… |
| 缺图占位 | `assets/img/placeholders/` | 不要动 `missing.svg` |
| UI 装饰字 | `assets/img/ui/` | ⚠️ 见下方警告 |

### 3.2 ⚠️ 四个文件是硬编码的，别改名

`index.html` 里直接写死了这四个路径，改了名字首页会缺图：

```
assets/img/ui/pangtouyu.png      ← 首页左边角色名装饰字
assets/img/ui/gaojiaoniao.png    ← 首页右边角色名装饰字
assets/img/ui/sheding.png        ← "设定"按钮图
assets/img/ui/zhuanshu.png       ← "专属"按钮图
```

### 3.3 体积控制

站点是纯静态的，图片直接吃带宽。建议：

- 物品图标：≤ 128×128，PNG-8 或 WebP，单张 **< 50 KB**
- 角色立绘：长边 ≤ 1024，**< 400 KB**
- 首页海报：长边 ≤ 1600，**< 800 KB**
- 能用 SVG 就用 SVG（现在那些占位图标都是 SVG，几 KB 而已）

压图工具：<https://squoosh.app>（在线）、`pngquant`、Photoshop「导出为 Web 所用格式」。

### 3.4 文件名用英文

中文文件名在本地 Windows 上能用，但部署到 Linux 服务器后有编码风险。**请统一用英文小写 + 下划线**。

## 4. 写更新日志

```js
{
  "id": "log_011",
  "title": "新增竹节笔与阴阳平衡调整",
  "version": "v0.2.0",
  "date": "2026-05-25",              // 必须 YYYY-MM-DD
  "image": "assets/img/items/terrain_token.svg",
  "changes": [
    "新增物品：竹节笔。",
    "阴阳值上限由 100 调整为 120。"
  ],
  "related": ["item_inkstone"]
}
```

**注意**：

- 数组**第一条**是最新的，会带一个「新」字印章
- 更新日志**不弹详情窗**，卡片里直接展示全部 `changes`
- `date` 不写 `YYYY-MM-DD` 格式会被校验脚本报错

## 5. 改分区顺序 / 增删分区

`sections` 控制导航栏和页面块：

```js
{ "id": "items", "title": "物品", "themeClass": "section--paper", "rootId": "items-root", "splitHeader": true, "filterButton": true }
```

| 字段 | 说明 |
|---|---|
| `id` | 必须和数据里的某个键同名（`items` / `mechanics` / `terrains` / `seasons` / `changelog`） |
| `title` | 导航和标题显示的文字 |
| `themeClass` | `section--paper` 白底 / `section--ink` 黑底，建议交替使用 |
| `rootId` | 内容容器 id。⚠️ `items` 和 `changelog` 的 rootId **被 render.js 写死了**，必须是 `items-root` / `changelog-root` |
| `splitHeader` | 只有物品区用，标题栏分离布局 |
| `filterButton` | 只有物品区用，显示「筛选」按钮 |

**想加一个新分区（比如「入门」「常见问题」）的完整步骤**：

1. 在 `sections` 里加一条：`{ "id": "guides", "title": "入门", "themeClass": "section--ink", "rootId": "guides-root" }`
2. 在顶层加数据：`"guides": [ { "id": "guide_start", "title": "如何开局", "summary": "…", "image": "…" } ]`
3. 刷新 —— 导航、分区、卡片全自动出现（`assets/js/data.js` 会自动发现未知的数组字段）
4. 进第 2 步之后建议顺手改一下 `assets/js/filter.js` 里的 `type_label`（见下一节）

## 6. 已知限制（改动前先看）

| 限制 | 影响 | 怎么办 |
|---|---|---|
| 角色 id 写死为 `pangtouyu` / `gaojiaoniao` | 改 id 会导致首页角色卡片塌掉 | 想换角色就换名字和立绘，**别改 id** |
| 只能显示 2 个角色 | 第 3 个角色起不会渲染 | 需要改 `assets/js/data.js` 的 `normalizeCharacters` |
| `owner` 标签写死在 `data.js` | 新角色的卡片缺少归属标签 | 改 `assets/js/data.js` 的 `ownerLabels` |
| 新分区的条目在全局搜索里没有类型标签 | 搜索结果显示为空白小灰字 | 在 `assets/js/filter.js` 第 86 行附近的 `type_label` 映射里加一行，如 `seasons: "季节"` |
| `items` / `changelog` 的容器 id 写死 | 改 `rootId` 会渲染不出来 | 别改，或同步改 `assets/js/render.js` |
| 更新日志不弹窗 | — | 设计如此，卡片内已展示全部内容 |

## 7. 提交前自检

```powershell
node tools\check_data.mjs
```

看到 `✓ 没有错误` 就可以提交了。警告里的「占位文案」是还没写完的提示，等全部替换成真内容就会消失。

浏览器里再走一遍：

1. 打开首页，两个角色立绘、属性、海报都正常显示
2. 点开每个物品，详情、配方、关联都正确
3. 打开 `?editor=1`，右下角校阅面板里**没有「死链」和「缺图」**
4. 搜一个词，能搜到刚写的内容
