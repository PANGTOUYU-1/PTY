# 部署与发布

把这个文件夹变成一个 GitHub 仓库，并让它自动上线。

---

- 一个 GitHub 账号（当前项目在 `PANGTOUYU-1` 名下）

## 2. 把本地文件夹初始化成仓库

```powershell
cd "D:\你的路径\dao-yinyang-site"

git init
git add .
git commit -m "init: 我们饥佬是这样的 wiki 站点骨架"
```

已经 clone 过仓库的话，把文件复制进去再 `git add .` 即可。

关联远程仓库（HTTPS 方式）：

```powershell
git remote add origin https://github.com/PANGTOUYU-1/PTY.git
git branch -M main
git push -u origin main
```

## 3. 部署方式 A：GitHub Actions（推荐，已配好）

仓库里已经有 `.github/workflows/pages.yml`，推到 `main` 就会自动部署。

**只需做一次设置：**

1. 仓库页 → **Settings** → 左侧 **Pages**
2. **Source** 选 **GitHub Actions**（不要选 Deploy from a branch）
3. 回到仓库 → **Actions** 标签，应该能看到「部署到 GitHub Pages」在跑
4. 跑完后地址是：

```
https://PANGTOUYU-1.github.io/PTY/
```

**之后每次更新：**

```powershell
git add .
git commit -m "content: 补充竹节笔词条"
git push
```

推送后 Actions 会自动重新部署，大约 30 秒～2 分钟生效。

**这个 workflow 干了什么：**

```yaml
mkdir -p dist
cp -r index.html assets data .nojekyll dist/   # 只发布站点文件，不发布 docs/ tools/ README
```

好处：仓库里的文档、工具脚本不会暴露到线上。

---

## 4. 部署方式 B：直接用分支部署

不想用 Actions 的话：

1. **Settings** → **Pages** → **Source** 选 **Deploy from a branch**
2. Branch 选 **main**，目录选 **/(root)**
3. 保存，等一两分钟

仓库里已经放了 `.nojekyll`，这个空文件的作用是**阻止 GitHub 用 Jekyll 处理站点**。少了它，个别以下划线开头的文件会被吞掉。本项目目前没有这类文件，但留着更稳。

⚠️ 这种方式会把 `README.md`、`docs/`、`tools/` 也一起发布到线上（能直接访问到）。不介意的话没关系。

---

## 5. 自定义域名（可选）

1. 域名 DNS 加一条 CNAME 记录，指向 `PANGTOUYU-1.github.io`
2. **Settings** → **Pages** → **Custom domain** 填入域名
3. 勾选 **Enforce HTTPS**

用 Actions 部署时，自定义域名配置由 GitHub 保存，不会因为你重新部署而丢失。

## 7. 故障排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 线上整页白屏，控制台报 404 | **文件名大小写不一致**。Windows 不区分大小写，Linux 区分 | 把路径和实际文件名逐字对齐（`Assets/Img` ≠ `assets/img`） |
| 图片本地能看，线上裂图 | 同上，或文件名里有中文/空格 | 改英文文件名，重新提交 |
| 页面加载了但没内容 | `data/site-data.js` 有 JS 语法错误 | 按 F12 看 Console 报错；跑 `node tools\check_data.mjs` |
| 导航栏只有「序」 | `sections` 为空或数据解析失败 | 检查 `site-data.js` 是否有语法错误 |
| 物品区空白 | `sections` 里 `items.rootId` 不是 `items-root` | 改回 `items-root` |
| Actions 报 `Resource not accessible by integration` | Pages 的 Source 没选 GitHub Actions | Settings → Pages → Source 改成 GitHub Actions |
| Actions 报权限错误 | workflow 的 `permissions` 被改过 | 确认有 `pages: write` 和 `id-token: write` |
| 改了没生效 | 浏览器缓存 | 强刷 Ctrl+F5；`serve.py` 已禁用缓存 |
| `?editor=1` 打不开 | 用 `file://` 双击打开了 | 必须走 `http://` |

## 8. 网络问题（当前环境实测）

这台机器目前**无法访问 github.com**：

| 检查 | 结果 |
|---|---|
| `github.com` DNS 解析 | `198.18.0.135`（保留网段，是本地代理软件的 fake-ip） |
| `curl` 直连 | 连接失败（`000`） |
| `curl` 走本地代理 `127.0.0.1:12450` | 连接失败（`000`） |

代理端口在监听，但**没有可用上游**。需要检查：

- 代理软件是否真的在运行、节点是否可用、订阅是否过期
- 是否开了 TUN 模式但路由没生效

修好之后再 `git push`。

### 备选托管方案

GitHub Pages 在国内访问时常不稳。本站是**纯静态**（无后端、无构建），换平台几乎零成本：

| 平台 | 特点 |
|---|---|
| **Cloudflare Pages** | 免费、全球 CDN、直连 GitHub 仓库自动部署 |
| **Vercel** | 同上，配置最简单 |
| **Netlify** | 拖拽文件夹就能发布 |
| **Gitee Pages** | 国内快，但需要实名且审核 |

除 Gitee 外，其余平台都支持「连接 GitHub 仓库 → 每次 push 自动部署」，配置文件都不需要写（本项目没有构建命令，发布目录填 `/`）。
